# HTML 学习笔记设计规范

## 1. 目标

HTML 学习页不是 Markdown 的换皮副本，而是为了让人愿意打开、能快速恢复解题思路的视觉化复习材料。

每一页必须同时做到：

1. **好看**：有明确、克制且与主题相关的视觉方向，不呈现通用 AI 模板感；
2. **好学**：先给记忆锚点，再给必要推导，最后对应到实际代码；
3. **好维护**：离线、无脚本、复用共享样式，Markdown 与源代码继续独立保留；
4. **好验证**：桌面、手机、深浅色、键盘和打印都能正常阅读。

## 2. 生成前必须做什么

1. 先确定主题、受众、页面唯一任务、教学模型和视觉方向，再加载技能；技能不能代替内容判断。
2. 加载 `creative/frontend-design`（使用完整限定名，避免本机同名技能歧义）。若 `ui-skills-root` 可用，按 `docs/AI前端技能与可选工具.md` 使用 `npx --yes ui-skills@0.2.4` 选择最具体的一个专项技能；复杂任务最多两个，与基础技能合计不超过三个。
3. UI Skills 未安装、网络或 npm 不可用时，直接使用本地前端设计技能与本规范降级完成，不得阻塞添加资料或转而复制旧页面。
4. 需要设计语汇时，可参考 `popular-web-designs` 中适合阅读内容的 Notion、Mintlify 等体系；借鉴信息层级、留白、字体尺度和边界处理，不照搬品牌或远程资源。
5. 检查同题 Markdown、用户 AC 代码与 `_说明.md`，只读取必要目录，不扫描整个知识库。
6. 具体题目先从源材料中分离并完整保留“题目描述 → 输入 → 输出 → 数据范围 → 样例”，再把长题解压缩成“触发信号 → 核心转化 → 关键证明 → 代码对应 → 易错点 → 速记”。完整题面与精简题解是并列层，不互相替代。
7. 选择一个真正来自题目内容的记忆锚点，例如平衡线、树的切边、状态机、时间轴或网格，而不是无意义渐变球。

外部技能只提供专项建议，不能覆盖本项目的静态离线、严格 CSP、无脚本、完整题面、AC 代码原样保留和不套版要求。不要为同一目的重复安装或加载多个泛化技能。

## 3. 文件结构

```text
算法大类 / 可复用题型 / 题号 - 题名 - 核心知识描述/
├─ _说明.md
├─ 题名 - 核心方法.html       # 首选阅读页
├─ 题名 - 核心方法.md         # 备用文本版
└─ 题名.cpp                   # 用户 AC 代码或参考实现
```

`_说明.md` 中写：

```yaml
entry: 题名 - 核心方法.html
```

HTML、Markdown 与代码都应保留。首选入口只决定优先打开谁，不改变完整文件列表。

## 4. 内容结构

不是每页都必须使用完全相同的章节数量，但至少覆盖以下信息：

- **完整题面（具体题目必需）**：保留用户提供的题目背景与任务、输入格式、输出格式、数据范围和样例。可以优化排版，但不能用摘要替代原题、擅自删掉条件或改写含义；源材料缺项时标明“源材料未提供”，不能自行猜测。纯知识点页面没有独立题面时不需要此节；
- **题目模型**：在完整题面之后另行提炼，只保留理解算法所需的变量、条件与目标，用于快速进入解法；
- **核心结论**：进入页面第一屏就能看到；
- **关键转化/推导**：每一步说明“为什么”，公式必须完整、可直接阅读；
- **视觉模型**：用流程、对照表、分区图或时间轴承载真实逻辑；
- **与实际代码对应**：保留关键函数、变量和局部控制流的针对性讲解；
- **完整代码与程序总览**：HTML 中展示与同目录 CPP 一致的完整 AC 代码，并解释整份程序的状态组织、调用顺序、输入输出和边界；已在函数区解释过的内容不再逐行重复；
- **易错点**：只写真正会导致 WA、RE 或理解偏差的细节；
- **复杂度与边界**：简短明确；
- **比赛速记**：把整页压缩为 4～7 个可复现要点；
- **关联文件**：链接到 Markdown 与 CPP。

用户明确说明代码已经 AC 时，不再随机对拍，也不擅自改成另一种代码风格。HTML 中的完整代码必须来自该 CPP，只允许为 HTML 显示进行字符转义；不得删减 include、空行或看似无用的模板内容。可以指出风险，但要把“已通过实现”和“可选改进”分开。

代码讲解分成两层：

1. **函数/片段层**：继续解释真正承载算法的函数、状态或关键语句；
2. **整份程序层**：解释初始化、预处理、核心函数调用、答案形成与输出之间怎样连接。

完整代码区不再重复逐行讲解前面已经解释过的函数。它的作用是让学习者把局部算法重新放回一份可提交程序中，而不是制造第二份相同注释。

## 5. 视觉质量标准

### 5.0 差异化硬性要求

项目不提供可复制的学习页 HTML 成品模板。`docs/学习页安全与质量底线.md` 只记录 CSP、离线资源、可访问性和验收约束，不提供固定 DOM 或章节顺序。每次新建页面都必须先完成本题教学设计，再对照最近 2～3 个同类 HTML 识别并避免重复，不能挑一页继续套用其首屏、卡片顺序和视觉语汇。

新页面至少要在下列四项中完成两项明显的主题化差异：

1. 首屏构图；
2. 与知识内容直接相关的视觉锚点；
3. 章节组织与阅读节奏；
4. 主辅色与版式细节。

如果只改了标题、标签、公式和代码，视为不合格。英文小标题、机械的 `01/02/03` 编号、统一“金句卡片”和渐变装饰都不是默认必需项；只有内容确实需要时才使用。正文要像认真做的个人复习笔记，少用“最关键的是”“本质上就是”“一眼秒懂”等重复 AI 套话。

### 5.1 必须具备

- 清晰的标题层级、舒适正文行宽和稳定垂直节奏；
- 一种主强调色与一种辅助强调色，正文对比度足够；
- 有意义的页内导航、核心结论卡、公式块、代码块与速记区；
- 桌面端有充分留白，移动端自然收为单列；
- 深色与浅色主题都经过检查；
- 可见键盘焦点，遵守 `prefers-reduced-motion`；
- 打印时移除不必要导航并保持正文清晰。

### 5.2 明确禁止

- 只替换标题和正文、所有题目长得完全一样的机械套版；
- 把最近一页的 DOM 顺序、首屏构图和全部组件原样复制到下一页；
- 大量无意义圆角卡片、随机渐变、发光球和与内容无关的装饰；
- 为了显得“高级”滥用英文眉题、全大写标签、机械编号和口号；
- 为“高级感”牺牲字号、对比度、代码可读性或移动端体验；
- Google Fonts、CDN CSS、远程图片、MathJax/KaTeX、第三方脚本；
- `<script>`、内联事件、表单、自动联网和跟踪代码；
- 完整代码与同目录 CPP 不一致，或为了“整洁”擅自删改用户已经 AC 的写法；
- 在函数讲解和完整代码讲解中重复同一套逐行说明，拉长页面却没有增加整体理解；

## 6. 共用与个性化边界

`static/note.css` 负责：

- 颜色变量与基础字体回退；
- 阅读容器、标题、目录、公式、代码、表格、结论卡；
- 深浅色、响应式、打印、焦点和减少动画；
- 所有题目都受益的通用修复。

具体 HTML 负责：

- 与题目匹配的信息结构；
- 真正有教学价值的图示、对照和内容顺序；
- 本题特有的记忆锚点与强调语句。

不要把题目名称或特例写入主站 `catalog.js`、`style.css` 或扫描器。若一个视觉组件连续在多页复用，再抽到 `note.css`。

## 7. 安全与离线要求

- 只引用同源 `/static/note.css` 与同目录资料；
- 不引用 `http://`、`https://`、协议相对 URL 或远程字体；
- 不包含 `<script>`、`style=`、`onclick=` 等内联执行入口；
- 图片优先放在同题目录并使用相对地址；小型纯装饰可用 CSS；
- HTML 必须在知识库严格 CSP 下完整可读；
- 公式优先使用清晰文本公式块；需要更强语义时可使用浏览器原生 MathML。

## 8. 验收清单

### 内容

- [ ] 首屏能看见题目能学到什么与核心结论；
- [ ] 具体题目完整保留题目描述、输入、输出、数据范围和样例，HTML 与 Markdown 内容一致；题目模型另列，没有取代完整题面；
- [ ] 源材料缺失的题面部分已明确标注，没有根据经验猜测题目条件或样例；
- [ ] 没有长题解的重复铺陈；
- [ ] 公式符号完整，没有 `\\[`、`\\sum`、断裂等乱码；
- [ ] 代码片段与用户实际代码一致；
- [ ] HTML 展示完整 AC 代码，反向还原后与同目录 CPP 完全一致；
- [ ] 有整份程序的状态组织与执行流程讲解，且没有重复函数区的逐行说明；
- [ ] Markdown、CPP 与其他附件仍保留。

### 视觉与交互

- [ ] 1440px 桌面无横向溢出，正文行宽舒适；
- [ ] 390px 移动端无页面横向溢出，代码块可局部滚动；
- [ ] 深色、浅色均有足够对比度；
- [ ] 键盘 Tab 能看见焦点；
- [ ] 打印预览没有截断重要内容；
- [ ] 页面具有与主题相关的视觉记忆点，而不是默认模板感。
- [ ] 已与近期同类 HTML 对照，至少有两项可说明的主题化差异。

### 集成

- [ ] `_说明.md` 的 `entry` 指向本目录 HTML；
- [ ] `/api/catalog` 中 `primary_file` 正确；
- [ ] 目录页显示“打开学习笔记”，点击能打开 HTML；
- [ ] HTML、MD、CPP 等仍全部显示在直属文件列表；
- [ ] HTML 响应 CSP 禁止脚本和联网；
- [ ] 相关文档、测试报告与 `CHANGELOG.md` 已更新。
