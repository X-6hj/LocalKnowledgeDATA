# 维护与扩展

## 日常维护

- 正式资料只放在 `library`，程序文件与资料分离。
- 任意目录需要标题、摘要、标签或正文说明时使用 `_说明.md`。
- 一级目录需要图标和根索引顺序时可使用 `_分类.md`。
- `_分类.md`、`_说明.md` 可参考 `templates` 中的元数据格式，减少字段拼写错误。
- 项目不保留可复制的学习页 HTML 成品模板；新页面先读 `docs/学习页安全与质量底线.md`，再按主题独立完成教学结构、视觉设计和验收。
- 定期备份 `library`、`config.json` 和自己修改过的源码。
- `logs/server.log` 自动轮转：单个约 1 MB，保留 3 个备份。
- `KNOWLEDGE_ROUTING.md` 与 `KNOWLEDGE_STRUCTURE.md` 是可再生运行快照：可读取，不手改、不备份为多个版本、不提交 Git。

## 目录维护原则

1. 目录深度不设固定上限，但应按真实知识关系嵌套，不要为了视觉缩进建立无意义空层。
2. 一个目录只描述本级主题；文件放在最具体、最合适的目录。
3. 本级目录的 `files` 只包含直属文件，后代统计由扫描器聚合，维护者不要手工生成索引 JSON。
4. 移动或重命名目录会改变相对路径和节点 ID；该目录的浏览器收藏需要重新添加。
5. 不要把缓存、临时下载、构建输出或快捷方式放入正式目录。

## 从其他目录迁移资料

涉及“迁移后删除原文件”时，必须按以下顺序：

1. 在 `library` 中按需要创建任意深度的目标目录树和说明；
2. 复制原文件，不要先移动或删除；
3. 比较源/目标文件大小和 SHA-256；
4. 从目标位置实际读取文件，并确认 `/api/catalog` 的对应 `folders[].files` 已索引；
5. 仅删除已核验的原文件，不顺带删除同目录其他内容；
6. 在 `CHANGELOG.md` 或迁移记录中保存来源、目标和哈希。

## 配置

根目录 `config.json`：

```json
{
  "title": "拾页星图 · 本地知识库",
  "subtitle": "把散落的资料，整理成可抵达的知识坐标。",
  "port": 8765,
  "refresh_seconds": 5
}
```

修改端口后，还要同步修改四组 Windows/WSL 启动器中的本地 URL。

## 修改扫描器时的约束

- `folders` 是新版主模型；新增目录能力优先扩展该字段。
- `categories/items` 仅用于兼容旧客户端，不应承载新的目录语义。
- 保持 `files` 为直属文件，子树统计使用独立字段。
- 聚合应采用一次扫描和自底向上传播，避免对每个节点再次遍历全部后代。
- 不要把后代完整文件列表复制到每个祖先；深层目录多时会放大内存。
- 扫描和 revision 必须共用 `_walk_visible()`；隐藏目录、符号链接和 junction 应在遍历入口剪枝，不能只在结果阶段过滤。
- 新字段需要补充最少一个深度大于 2 的单元测试。
- 首选入口由扫描器生成，前端不得按扩展名或题目名称重复实现选择规则。

## 修改前端时的约束

- 数据刷新后统一重建 `path → folder` 与 `parent_path → direct children` 索引。
- 普通目录浏览只渲染当前直属子目录；只有全库搜索遍历全部节点。
- 对搜索文本做一次标准化缓存，不要在每次输入时重复拼接全部字段。
- 文件类型筛选使用 `descendant_file_types`，卡片文件列表仍使用直属 `files`。
- 新交互必须同时检查桌面、390px 移动端、键盘焦点和无横向溢出。
- 当前目录必须同时保留首选入口与完整直属文件列表；不能为了突出 HTML 隐藏 Markdown 或附件。
- 完整结构树只在 `structureDialog` 打开时渲染，关闭时释放 DOM；不要把整棵树常驻到主页面。
- 总览跳转必须复用 `enterFolder(path)`，不能另建一套当前位置状态；默认完整展开目录但文件按需显示。
- 普通展开状态与搜索临时折叠状态必须分离；搜索箭头不得被“匹配路径强制展开”覆盖，关键词变化后应清空旧搜索状态。
- 总览打开时必须通过 `currentPath` 的祖先链定位 `aria-current="page"`；定位只滚动总览自身，不改变主页面焦点或当前位置。
- 桌面宽度统一经 `setupStructureResize()` 限幅和持久化；移动端固定全屏。调整宽度边界时同步检查指针、键盘、ARIA 数值和本地存储键 `kb:structure-width`。

## 修改 AI 选址与双快照时的约束

1. `library/` 和 scanner catalog 始终是唯一事实来源，Markdown 快照与网页树只能消费 catalog，不能各自扫描磁盘。
2. 保持根目录固定文件名 `KNOWLEDGE_ROUTING.md` 和 `KNOWLEDGE_STRUCTURE.md`；不要生成时间戳、编号或历史副本。
3. 保持“内容相同不改写 + 同目录唯一临时文件 + `flush`/`fsync` + 原子替换”，避免半写文件和无意义修改时间变化。
4. 快照含个人路径信息，必须继续留在 `.gitignore`；临时文件模式也必须忽略。
5. 快照写入失败不得使 `/api/catalog` 不可用，但需要记录明确 warning；独立脚本失败则应返回非零状态。
6. 新增快照或候选字段时只使用 catalog 已有事实，并补充确定性输出、空目录、特殊字符、候选上限、重复提示或故障降级测试。
7. 若目录规模增长到浏览器实测卡顿，优先拆分结构模型/视图并采用分片或虚拟化，不改变 API 的扁平节点契约。
8. `/api/catalog` 必须只读缓存；后台刷新只能有一个线程并由刷新锁串行化。服务关闭时必须停止线程，启动扫描失败时必须释放 socket 和日志句柄。
9. 轻量探测使用 `tree_signature()`；只有签名变化才完整解析。发布新 catalog 前保留扫描前后签名检查，扫描中持续变化时不得覆盖已经稳定的缓存。
10. `query_placement()` 必须保持纯函数、稳定排序和精简输出；CLI 与 `/api/placement` 复用它，不分别实现评分。默认最多 3 个候选，服务端硬上限为 5。
11. `_说明.md` 的 `placement: route|leaf` 是人工覆盖入口；自动模式应保守排除含直属资料的末级目录，避免把具体题目当作父分类。

## HTML 学习页维护原则

1. 动手前加载 `creative/frontend-design`（完整限定名）；需要设计语汇时再参考 `popular-web-designs` 中适合阅读型内容的 Notion/Mintlify 等方案。不要为同一目的重复安装低质量技能。
2. 每个主题先确定一个与内容有关的视觉方向和“记忆锚点”，再使用共享 CSS；安全质量文档只负责底线，不提供可复制 DOM，也不替代设计判断。
3. 禁止第三方 CDN、远程字体、脚本和内联事件；学习页应在断网时完整可读，并兼容知识库 HTML 的严格 CSP。
4. 必须有清晰标题、短摘要、页内导航、核心结论、关键推导、AC 代码对应、完整 AC 代码、程序整体执行流程、易错点/复杂度和速记区；删去重复铺陈。
5. 函数/片段区负责局部算法解释；完整代码区负责呈现可提交程序，程序总览负责串联状态、调用和输出。不得在两个区域重复同一套逐行讲解；完整代码反向还原后必须与 CPP 一致。
6. 必须检查 1440px 桌面、390px 移动端、深浅色、键盘焦点、打印预览和横向溢出。视觉检查不能由语法检查替代。
7. 共享视觉修复优先进入 `static/note.css`；某题独有的图示和结构写在该 HTML 中，不把题目特例堆入全局样式或主站 JS。

## 性能回归

当前参考基准（WSL `/tmp` 临时数据）：

| 数据规模 | 扫描时间 |
|---|---:|
| 1,040 目录、1,000 文件 | 约 0.1592 秒 |
| 2,080 目录、2,000 文件 | 约 0.2719 秒 |

数据翻倍时耗时约 1.708 倍。修改扫描逻辑后应使用同类基准比较增长趋势；硬件不同可以绝对时间不同，但不应出现明显平方级增长。

## 升级建议

### 全文检索

资料达到数千条或需要搜索 PDF/Word 内文时：

1. 增加文本提取器，把正文写入缓存目录；
2. 使用 SQLite FTS5 建立本地全文索引；
3. 增加 `/api/search`，返回目录路径和来源片段；
4. 原文件与目录树仍是唯一事实来源。

### OCR 与本地 AI

只对扫描件按需 OCR 并缓存结果。本地问答采用“检索 → 候选片段 → 模型回答 → 文件与页码引用”，不得让模型替代目录或检索事实。

### 局域网共享

当前服务没有身份验证，不应把 host 改为 `0.0.0.0`。若要共享，应增加登录、只读权限、TLS 和防火墙规则后再显式开放。

## 发布前检查

```bash
cd <项目所在的 WSL 路径>
python3 -m py_compile run.py stop.py src/*.py tests/test_core.py
python3 -m unittest discover -s tests -v
node --check static/catalog.js
node --check static/app.js
python3 query_placement.py --title "示例" --keywords "数论 质数" --limit 3 --json
python3 generate_structure.py
```

还要用项目便携 Windows Python 运行同一轮单元测试，并真实检查 `/api/health`、`/api/catalog`、固定结构快照、结构总览首次完整展开、从深层目录自动定位、普通/搜索状态折叠、目录跳转、左边缘拖动、键盘调宽、宽度记忆与复位，以及三级以上目录导航、面包屑、各级说明、全库搜索、子树文件类型筛选、桌面和 390px 移动端布局。移动端应确认调宽控件禁用且无横向溢出。纯 Windows 发布还应验证正常 PID 停止和 PID 文件丢失后的安全恢复停止。

如果后续增加多选、文件预览或高级查询，不要继续把功能直接堆入 `catalog.js`；先拆分目录模型、结构树视图和应用控制器。只有全库搜索或总览在数千目录下出现真实延迟时，再引入 debounce、分片、分页或虚拟化。
