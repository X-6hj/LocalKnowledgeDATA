# 架构设计

## 设计目标

1. 添加资料时不手工修改 HTML；
2. 支持 PDF、Office、图片、压缩包等任意文件；
3. 支持任意深度目录，并让每一级都可以有独立说明；
4. 目录和文件数量增长时保持近似线性的扫描成本；
5. 数据默认不离开本机，运行时零第三方 Python 依赖；
6. 为 AI 和人提供低成本全局结构入口，不要求反复扫描资料目录；
7. 后续能增加全文检索、OCR 和本地 AI，而不更换资料目录。

## 技术方案

```text
library 任意深度目录树
    ↓ 单次目录扫描、元数据解析、自底向上聚合
src/kb_scanner.py
    ↓ 扁平节点 JSON（path + parent_path + primary_file）
    ├─ src/knowledge_structure.py → KNOWLEDGE_STRUCTURE.md（固定、原子覆盖）
    └─ src/kb_server.py  ── /api/catalog /api/open /files/*
                              ↓
HTML + CSS + 原生 JavaScript
    ↓ 构建 path→节点、parent→直属子目录索引
逐级导航 / 面包屑 / 全库搜索 / 按需渲染的完整结构总览
```

- **Python 标准库**：负责目录扫描、元数据、HTTP 服务、日志、安全路径校验和系统文件打开。
- **扁平节点模型**：API 不输出递归嵌套对象，而是让每个节点保存 `path` 与 `parent_path`。这样深层目录不会造成递归 JSON 处理困难，前端也能按父路径 O(1) 取得直属子目录。
- **原生前端**：负责导航、筛选、悬浮说明、响应式和可访问性，不把文件系统规则塞入浏览器。
- **双重结构出口**：同一份 catalog 同时驱动网页结构总览和 Markdown 快照，不再各自重新扫描或维护两套目录规则。
- **无数据库**：任意深度的文件夹结构仍是唯一事实来源，复制和备份直观。

## 目录节点模型

`GET /api/catalog` 使用 `schema_version: 2` 标识当前契约，主数据字段为 `folders`。前端会先校验接口版本；不兼容时提示重新启动服务，避免新前端连接旧进程后产生难懂的 JavaScript 异常。每个目录节点包含：

| 字段 | 含义 |
|---|---|
| `id` | 由相对路径生成的稳定短 ID；路径改变时 ID 随之改变 |
| `path` | 相对 `library` 的 POSIX 风格路径 |
| `parent_path` | 直属父目录路径；一级目录为空字符串 |
| `depth` | 一级目录为 1，依次递增 |
| `title/summary/description/tags` | 本级目录元数据 |
| `files/file_types` | 仅本级目录直属文件及其类型，永远保留完整列表 |
| `primary_file` | 本级首选入口的完整文件记录；无首选入口时为 `null` |
| `child_count` | 直属子目录数量 |
| `descendant_count` | 所有后代目录数量 |
| `descendant_file_count` | 整个子树文件数量 |
| `descendant_file_types` | 整个子树包含的文件类型 |
| `order/pinned/modified` | 排序与更新时间信息 |

`categories` 和 `items` 继续返回以兼容旧客户端：

- `categories` 对应一级目录；
- `items` 对应二级目录，并合并其子树文件；
- 顶层 `types` 保持旧客户端口径：统计“包含该格式的兼容条目数”，不是物理文件数；物理文件总数使用 `stats.files`；
- 新功能只应基于 `folders` 开发，兼容字段不会扩展新的目录语义。

## 元数据规则

- 任意目录：按 `_说明.md`、`_meta.md`、`说明.md`、`README.md` 的优先级寻找说明。
- 一级目录：额外兼容 `_分类.md`、`_category.md`。
- 一级目录同时存在分类与说明元数据时，先读取分类元数据，再由说明元数据覆盖同名字段；正文优先使用说明正文。
- 元数据文件不作为普通附件返回。
- 前端始终使用 `textContent` 展示说明，不执行 Markdown 内的 HTML 或脚本。
- `entry` 只能按文件名命中本目录 `files`，拒绝 `/`、`\` 等路径分隔符；无有效显式入口时回退到按名称排序后的第一个 HTML/HTM。

## 首选学习入口

首选入口的选择属于扫描器职责，前端只消费 `folder.primary_file`，不根据文件名、题号或扩展名自行猜测。这样以后可以扩展 PDF 首页、交互演示或其他首选资料，而不在 UI 中堆积题目特例。

进入目录后，前端在直属文件列表上方渲染首选入口。原 `files` 数组不删、不去重，因此 HTML、Markdown、CPP、PDF 等仍保留相同的查看和系统打开能力。

HTML 学习页统一引用 `/static/note.css`，但具体页面必须依据主题内容组织信息结构，不允许只做机械模板换字。`templates/学习笔记.html` 提供语义骨架，`docs/HTML学习笔记设计规范.md` 定义设计质量门槛。代码学习内容采用两层结构：局部函数区解释算法关键点，完整代码区原样展示同目录 CPP 并以程序总览串联状态、调用和输出，避免重复逐行讲解。

## 导航与搜索

页面每次收到新目录数据时构建两个内存索引：

```text
Map<path, folder>
Map<parent_path, direct_children[]>
```

普通导航只读取 `direct_children[currentPath]`，因此 DOM 数量只与当前目录的直属子目录数量有关，而不是与全库总目录数有关。全库搜索才遍历全部节点，并使用数据同步时预先生成的标准化搜索文本。

文件类型筛选使用 `descendant_file_types`，因此深层文件可以使祖先目录命中筛选；进入目录后仍只展示该层直属内容。

## 全局结构快照与网页总览

`src/knowledge_structure.py` 把 catalog 的扁平节点重组为确定性的 Markdown 树，输出到根目录唯一固定路径 `KNOWLEDGE_STRUCTURE.md`：

- 服务创建时同步生成，保证浏览器打开前快照已经存在；首次扫描失败时关闭已绑定 socket 与日志资源；
- 运行中由唯一后台线程按 `refresh_seconds` 先做轻量目录签名探测，只在 `revision` 变化时完整扫描并重建，因此不依赖浏览器轮询；
- `/api/catalog` 只读取后台维护的缓存，不让并发 HTTP 请求重复扫描；刷新由独立锁串行化，发布前比较扫描前、扫描结果和扫描后签名，不稳定时重试一次或保留上一版等待下轮；
- 生成器先比较内容，相同则不触碰文件；变化时在同目录写唯一临时文件，执行 `flush`/`fsync` 后再以 `replace` 原子替换；目录名、文件名和摘要会清理控制字符及代码围栏字符；
- 快照失败只记录 warning，不让辅助索引阻断网页 catalog；
- `generate_structure.py` 复用相同扫描器和渲染器，供服务未运行时手工刷新；
- 该文件含个人目录和文件名，默认由 `.gitignore` 排除，不能当成需要提交的源文件。

前端“结构总览”使用 catalog 已有的 `path → folder`、`parent_path → children` 和标准化搜索文本，不增加第二个 API。总览采用模态侧边抽屉：首次打开完整展开目录但隐藏文件，只有对话框打开时才创建整棵 DOM；关闭后清空树节点。这样既满足全局认知，也不让日常逐级浏览长期承担整棵树的 DOM 成本。目录点击继续调用统一的 `enterFolder(path)`，因此原有面包屑、卡片和当前目录模型没有分叉。

总览交互状态按用途分离：`structureExpanded` 保存普通浏览的展开集合，`structureSearchCollapsed` 只记录当前搜索中被用户主动折叠的分支。搜索默认展开匹配链，但不再以 `queryActive` 强制覆盖按钮状态；关键词变化或关闭弹窗时清空临时集合。打开总览时，控制器始终沿 `currentPath` 展开祖先链，并在渲染后的下一帧以 `block: "center"` 请求滚动到 `aria-current="page"`；靠近树边界时浏览器会选择最近的可达位置，但始终保证当前项可见。当前位置定位与树渲染因此保持解耦。

桌面宽度由 `setupStructureResize()` 单独管理，通过 CSS 变量 `--structure-dialog-width` 交给布局层，限制在 420–960px 且为主页面保留至少 80px 视口。用户宽度写入本地键 `kb:structure-width`；拖动、方向键、边界键和双击复位共用同一个限幅函数。680px 及以下由媒体查询固定全屏并禁用分隔控件，避免触摸侧滑冲突。

## 性能设计

扫描流程分为四个线性阶段：

1. 枚举可见目录；
2. 每个目录读取一次直属项和本级元数据；
3. 按深度倒序把后代计数与文件类型集合聚合到父节点；
4. 单次遍历生成旧 `items` 兼容文件归属。

结构快照和前端树都复用 catalog，不自行扫描磁盘。后台轮询只执行轻量 `tree_signature()`；签名未变化时不解析元数据、不重建 catalog，也不触碰快照。网页树只在用户打开总览时渲染，默认页面仍只呈现当前直属目录。

扫描与公开的 `tree_signature()` 共用 `_walk_visible()`：遇到隐藏目录时立即剪枝，并默认忽略目录符号链接、断链和 Windows junction，不读取知识库边界外的名称或元数据。目录路径也进入修订签名，因此新增、删除或重命名空目录会触发自动刷新。

没有“对每个目录再次扫描全部后代”的平方级循环，也不会把深层文件列表复制到所有祖先。基准测试中：

- 1,040 个目录、1,000 个文件：扫描约 0.1592 秒；
- 2,080 个目录、2,000 个文件：扫描约 0.2719 秒；
- 数据量翻倍，耗时约 1.708 倍，符合近似线性增长预期。

这些数据用于回归趋势，不是不同硬件上的硬性 SLA。

## 为什么不直接双击 HTML

浏览器沙箱禁止普通网页自动枚举任意本地目录，也禁止网页直接启动系统程序。因此项目使用 `start-windows.vbs` 启动只监听 `127.0.0.1` 的轻量服务；项目自带便携 Python，不要求 WSL 或预装 Python。

## Windows 文件操作

- 默认打开：纯 Windows 使用 `os.startfile`；WSL 兼容模式通过编码后的 PowerShell ShellExecute。
- 选择应用：`windows_open_with.py` 调用 `SHOpenWithDialog`。
- 所在位置：使用 `explorer.exe /select, <路径>` 精确选择目标文件。
- 三种操作都先经过 `resolve_library_path`，不能访问 `library` 外部。

## 安全边界

- 默认绑定 `127.0.0.1`，不暴露到局域网；
- `/files/*` 和 `/api/open` 执行路径归一化并拒绝越界；
- `/api/open` 只接受 `application/json`，并拒绝非 `127.0.0.1`/`localhost` 同源的 `Origin`，防止恶意网页跨站触发本机文件操作；
- 说明以纯文本渲染；
- 响应包含 CSP、`nosniff`、拒绝嵌入等安全头；知识库 HTML 使用独立严格 CSP，禁止脚本、网络请求、表单、对象和外部基址，只允许同源样式、字体与本地/`data:` 图片；
- Windows 停止脚本只匹配带参数边界的精确项目 `run.py`，或“相对 `run.py` + 项目专用 Python 运行时”，避免误杀复用 PID 或同名前缀目录中的进程。
- 目录扫描不跟随符号链接或 junction，避免越过 `library` 边界。

## 扩展接口

- `GET /api/health`：服务健康状态与版本；
- `GET /api/catalog`：站点配置、统计、类型计数、目录节点和旧版兼容字段；
- `GET /files/<相对路径>`：安全提供文件，支持 Range；
- `POST /api/open`：仅接受本机同源的 `application/json`，执行 `{ "path": "任意深度/文件", "action": "default|choose|reveal" }`。

新增目录功能应扩展 `folders` 节点字段或增加独立 API，不要修改旧 `categories/items` 的含义，也不要在前端重新扫描路径字符串推断文件系统状态。`primary_file` 是向后兼容的可选字段，因此当前仍使用 `schema_version: 2`。

当前 `catalog.js` 同时承担目录状态派生与 DOM 渲染，`app.js` 负责总览事件、自动定位与尺寸控制；全局结构继续增长或需要多选、预览、高级查询时，应把 `structureSearchState`、树渲染、尺寸控制和事件控制拆为独立模块。全库目录达到数千级且实测出现打开或输入延迟时，再加入分片渲染、搜索防抖或虚拟化，避免为了当前小规模提前引入框架复杂度。
