# 学习页安全与质量底线

> 这是一份验收约束，不是 HTML 模板。不得复制某个现成页面或固定 DOM/章节顺序后替换文字；每个页面必须从题目教学模型开始独立设计。

## 先做教学设计，再写 HTML

1. 明确学习者第一次学习与赛前复习分别需要恢复什么；
2. 提炼题目模型、关键转化、证明依赖和最容易遗忘的边界；
3. 选择能承载真实逻辑的视觉锚点，例如状态转移图、切边、时间轴、区间覆盖或值域变化；
4. 根据认知顺序决定首屏、章节和信息密度，不默认沿用任何旧页面；
5. 对照近期 2～3 页只用于识别重复，不能挑一页继续套用。

如果无法说明“为什么这种结构适合这道题”，先停止写 HTML，重新完成教学设计。

## 不随题目变化的技术底线

- 共享样式只引用同源 `/static/note.css`；题目独有的布局和图示由本页独立定义；
- 不使用远程字体、CDN、远程图片、MathJax/KaTeX、跟踪请求或第三方脚本；
- 服务端严格 CSP 必须继续包含 `script-src 'none'`、`connect-src 'none'`、`form-action 'none'`；
- 页面不得包含 `<script>`、内联事件、表单或自动联网行为；
- 代码、表格、公式在窄屏中只能由可聚焦的局部容器横向滚动，页面本身不得横向溢出；
- 必须具备可见键盘焦点、深浅色可读性、`prefers-reduced-motion` 兼容和打印布局。

推荐样式引用只有这一条约束，不代表页面骨架：

```html
<link rel="stylesheet" href="/static/note.css">
```

## 具体题目的内容底线

- HTML 与 Markdown 都完整保留源材料给出的题目描述、输入、输出、数据范围和样例；缺项明确写“源材料未提供”，不能猜；
- 题目模型与精简题解另列，不能替代完整题面；
- 首屏应让人知道“这题训练什么、核心结论是什么”，但首屏构图不固定；
- 关键推导解释为什么成立，视觉化只服务于推理，不做无意义装饰；
- 用户声明 AC 的 CPP 原样保留；HTML 的完整 AC 代码由该 CPP 确定性转义，反向还原后逐字节一致；
- 局部函数区解释算法关键点；整体执行流程只串联状态、调用顺序、输入输出和边界，不重复逐行讲解；
- 易错点只记录真实会导致 WA、RE 或理解偏差的事项；
- 最后给出 4～7 条可复现的比赛速记，并链接同目录 Markdown 与 CPP。

## 差异化验收

每页至少能说明下列四项中的两项与近期页面有何主题化差异：

1. 首屏构图；
2. 内容化视觉锚点；
3. 章节节奏与阅读路径；
4. 主辅色、版式和代码/推导关系。

以下情况直接判定不合格：复制旧页面 DOM、固定章节顺序、机械 `01/02/03` 卡片、默认英文眉题、统一渐变装饰、只替换标题/公式/代码。

## 完成前验证

- 1440px 桌面与 390px 移动端；
- 深色与浅色；
- 键盘 Tab 与可见焦点；
- 打印预览；
- 页面级 `scrollWidth == clientWidth`；
- 严格 CSP 下无脚本、联网和表单；
- 完整 AC 代码与 CPP 一致；
- `/api/catalog` 的 `primary_file`、直属 `files` 和关联文件入口正确。
