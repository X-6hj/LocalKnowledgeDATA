# 公开发布与隐私

本项目的 GitHub `main` 分支只保存可公开复用的程序、文档、模板、已审计示例资料和当前验收证据。

## 默认边界

- `library` 是用户实际资料入口，因此新增内容默认由 `.gitignore` 排除。
- 当前仅明确公开 `library/示例资料`、已审计的 `library/计算机网络`，以及由单元测试夹具恢复的 `library/算法` 验收示例。
- 以后若要公开新的资料目录，应先检查姓名、学号、账号、联系方式、访问令牌、私有地址、聊天内容、私人文件名和版权边界，再为该目录添加显式放行规则。
- `.server.pid`、运行日志、Python 缓存、编辑器配置和临时下载永不进入公开提交。
- `qa/screenshots` 的新截图默认不提交；主分支只放仍被测试报告引用的当前验收截图。

## 历史资料

过时但仍可能有复查价值的、且经过隐私审计的验收材料放在独立远端归档分支中，不与 `main` 共同演进。这样日常克隆和更新不会下载历史材料，需要时仍可按分支取回。

可能暴露聊天侧栏、IDE 工程、个人窗口或本机调试上下文的原始截图不得上传到公开仓库。若确需长期保留，应放入私有存储，或先生成可靠脱敏副本。

## 发布前检查

```bash
python3 -m py_compile run.py stop.py src/*.py tests/test_core.py
python3 -m unittest discover -s tests -v
node --check static/catalog.js
node --check static/app.js
git diff --check
```

发布者还应检查：

1. `git status --ignored` 中是否有预期之外的资料；
2. 当前提交和将要推送的全部历史是否含凭据或个人路径；
3. 截图是否暴露其他应用、账户、聊天或私人文件；
4. GitHub 回读后的文件清单、默认分支和提交 SHA 是否与本地一致。
